# Sunday IPTV — SEO article writer

sundayiptv.com is **not WordPress**. Every page is generated by `_build/build.py`
from plain-text sources, then pushed to GitHub (`main` = live via GitHub Pages).
Never hand-edit the generated HTML: the next build overwrites it.

## 1. Confirm before writing

- Confirm the **topic and the focus keyword** with the user (French, e.g. « abonnement IPTV pas cher »).
- **Cannibalization check:** list existing articles (`GUIDES` and `DEVICE_GUIDES` in `_build/build.py`,
  files in `_build/articles/` and `_build/appareils/`) and grep them for the keyword.
  If a page already targets it, propose **improving that page** instead of writing a new one.
- **Search intent:** look at what currently ranks for the keyword (tutorial, comparison, quick answer)
  and match that format and depth.

## 2. Research — facts only

- Search the web in French; keep only facts you can verify on the source.
- Never invent specs, dates, prices, app names, download links or experiences.
- Never name a competitor IPTV provider or site.
- **Site facts** (use these, never different numbers):
  - Plans: 1 mois 12 €, 3 mois 25 €, 6 mois 30 €, 12 mois 60 € (`PLANS` in build.py — re-read it, prices may change).
  - 32 000+ chaînes, 220 000+ films et séries, essai gratuit 24 h, support WhatsApp 24/7.
  - One subscription = **one device at a time**.
  - Bandwidth: 10 Mb/s for HD. ⚠ 4K is inconsistent on the site (most guides: 40 Mb/s; Windows guide: ~25 Mb/s).
    Ask the owner which figure to use until this is resolved, and note the answer here.

## 3. Write the article (French)

Write `_build/articles/<slug>.txt`. Slug: short, lowercase, hyphens, keyword-based, no year.

### Source format (parsed by `parse_guide`)

```
## Titre de section          -> H2 (listed in the Sommaire)
### Sous-titre               -> H3
1. étape / - puce            -> numbered / bulleted list (one item per line)
> texte                      -> highlighted box
[[cta]]                      -> WhatsApp "Demander mon essai gratuit" box
![nom-image.jpg]             -> body image (alt text must be in IMG_ALT)
<table>…</table>             -> raw HTML on ONE line (tables, pros/cons)
Q: question / R: réponse     -> FAQ (rendered as accordion at the end)
**gras**, [ancre]({R}slug/)  -> bold, internal link   |  {brand} -> Sunday IPTV
```

⚠ Anything **before the first `##`** is dropped — the TL;DR goes inside the first section.

### Structure, in order

1. **First `##` section:** TL;DR as a `>` box (2–3 sentences answering the query), then a
   freshness line `Dernière vérification : <real date>`, then the intro in the team voice
   (« nous », « l’équipe {brand} »). Only claim experience the team really has.
2. `[[cta]]` right after the intro.
3. H2 sections with H3 subsections; **numbered steps** (`1.`) for every tutorial.
4. At least **one comparison table** (`<table>` line) where it helps the reader.
5. `[[cta]]` mid-article, and one `[[cta]]` inside the troubleshooting section.
   The 4th CTA (final block « Testez Sunday IPTV gratuitement ») is added automatically.
6. A conclusion section.
7. FAQ: **5–7** `Q:`/`R:` pairs with short, direct answers.

### SEO rules

- **Focus keyword placement:** title, first sentence of the intro, 1–2 H2s, meta description
  (= the summary), featured-image alt text. Elsewhere use natural variations and synonyms.
- **No keyword density target.** Sanity check only: if the exact phrase exceeds ~1.5 % of words,
  rewrite — it reads as stuffing. Report the exact-phrase count and word count to the user.
- **Length follows intent**, not a quota. Existing guides run ~1 100–2 000 words
  (the build prints each article's word count) — go longer only if the topic needs it.
- **Title:** keyword first. Add « (2026) » only if the article will really be updated yearly.
  Note: the H1 and `<title>` drop the « (…) » part; it only shows on the blog card.
- **Meta description** (= summary in `GUIDES`): 140–160 characters, keyword included, makes people click.
- **Internal links:** 3–6 links to existing pages, `[ancre descriptive]({R}slug/)` — only slugs that exist.
- **External links:** 2–4 authority sources (official app sites, regulators, speed tests) with descriptive
  anchors. Open each URL to confirm it is live before linking.
- Never add review stars or rating markup.

## 4. Images (3: featured + 2 body)

- Same style for all three: cozy photorealistic living room in the evening, people watching a big TV
  showing a colorful IPTV interface (tiles Live TV, Films, Séries, Sport, Enfants), **red LED-strip glow
  matching the site accent `#e63946`**, popcorn on the table, a short **bold, high-contrast French text
  hook** on the image (the keyword or a short phrase). No logos, no real brand marks.
- Give the user the 3 prompts; they generate the images and send them back.
- Save as JPG, **1200×800** (3:2), in `images/` with a descriptive name (`guide-<slug>.jpg`, `<slug>-1.jpg`…).
  WebP versions are created automatically by the build (needs Pillow).
- Add a French alt text for **each** image to `IMG_ALT` (featured alt contains the keyword).

## 5. Register the article in `_build/build.py`

- `GUIDES`: add `(slug, "Titre", "Catégorie", "icône", "Résumé = meta description")`.
  Icons: rocket monitor headset ban receipt calx diamond tv film check star clock shield globe
  phone box stick android apple laptop wrench chat mail pin wifi play book.
- `GUIDE_IMAGES`: `"slug": "guide-<slug>.jpg"` (featured image, shown under the intro and on cards).
- `RELATED`: 3 related slugs for the new article.
- **Link to the new article from 2–3 existing articles:** add a contextual sentence with a link in their
  `.txt`, and/or replace the weakest entry in their `RELATED` list.

## 6. Build and verify locally

```
python3 _build/build.py          # regenerates every page, the blog cards and sitemap.xml
python3 _build/link_audit.py     # must end with "liens cassés : aucun"
```

Serve the repo (`python3 -m http.server`) and check `/<slug>/` in a real browser (Playwright),
desktop and mobile:

- inside `.prose`: number of `.cta-inline` buttons = number of `[[cta]]`, each `href` starts with
  `https://wa.me/`; plus the final « Demander mon essai » block;
- steps render as `<ol>`/`<ul>` lists, the table as `<table>`, the FAQ as accordion items;
- featured image + both body images load (`naturalWidth > 0`), the Sommaire lists every H2;
- the exact keyword is in `<title>`, the meta description, the first paragraph, an H2 and the featured alt;
- take a screenshot and look at it.

## 7. Publish

- Commit on the working branch and push it. **Ask the user before merging into `main`** (main = live).
- After the merge, wait for the GitHub Pages deployment (Actions → « pages build and deployment »),
  then check live: `https://sundayiptv.com/<slug>/` returns 200 and renders (browser, not just a text
  fetch), the images load, and the URL is in `https://sundayiptv.com/sitemap.xml`.
- If something is wrong, **fix it in place and push again — never change the slug** of a published article.

## 8. Report and record

- Report: live URL, word count, exact-keyword count, internal/external links added, anything you could
  not verify.
- Suggest Search Console → URL Inspection → « Demander une indexation » for the new URL (the sitemap
  is updated automatically).
- Append any content gap you noticed to `_build/content-gaps.md` (create it if missing) as ideas for
  the next articles.
